# PRACTICES

> **AGENTS: maintain this file with Haiku or a similar-class model, in grok'd prose.** Style rules: [QUIET](QUIET.md), [PROSE](PROSE.md).

This file sets out how `.agents/` and the code around it are built. Each practice says what it means here and what checks it.

## 1. Progressive disclosure

Read the least that lets you act. Open more only when the task needs it.

- [AGENTS.md](../../../AGENTS.md) is a short entry: working rules and a link to ATLAS.
- [ATLAS](../../ATLAS.md) maps every path to one detail file. Open only the row you need.
- Indexes stay compact, with one line per record in `MEMORY.md` and `OPEN.md`. The detail lives in the record.
- Link, don't copy. A doc that needs another doc's detail links to it, and says when to open it.

## 2. Documents are graph edges

Write so an agent can walk from any file to what it depends on, and to what depends on it.

- Link on first mention, with a relative link whose text names the target: `[NOTATION](NOTATION.md)`.
- No orphans. A file nothing links to can't be found, so [ATLAS](../../ATLAS.md) or the rules table in `AGENTS.md` must reach every doc.
- Give the reason for each edge, in an "Open when" cell in a table or as "needs X" in a sentence.
- Keep edges short. ATLAS links to a leaf in one step, not through a chain of "see also".
- Records carry typed edges, not prose: `depends`, `ref(kind)`, `parents`, `covers`, and `[[id]]` inside a memory body.
- Checked: `write check` fails on a `ref` that doesn't resolve. `check-docs` fails on a broken doc link and on a doc nothing links to.

## 3. Don't repeat yourself

Each fact lives in one place. Everything else links to it or calls it.

- Grammar and placeholders live in [NOTATION](NOTATION.md), field limits in the template, and reason codes in `reasons.closure`.
- A change to one fact should touch one file. If it touches three, the fact is repeated: find its home and link to it.
- Code works the same way. A helper needed twice moves to one place and gets called from both. It is not copied.

## 4. Anti-monolithic

Build small pieces with one job each. They compose through files, JSON and exit codes.

- One tool, one job: `write` files records, `lint` lints Swift, `check-docs` checks docs. If you describe a file with "and" twice, it has two jobs: split it.
- Compose by contract. Tools talk through closure records, one JSON envelope on stdout, and exit codes. They don't reach into each other's internals.
- Hooks stay thin: read the hook input, call a tool, and return its exit code.
- A script is one `.swift` file ([SCRIPTS](SCRIPTS.md)). Keep each one small enough to read in a sitting. Share behavior by calling another tool through `bin/`.

## Hand-maintained docs

Every `.md` the writer doesn't generate starts with the `> AGENTS:` banner above, under its title. Files generated by `write render` say so in their first lines and are never edited by hand. `check-docs` checks both.
