# Closure System Skill

This skill guides agents on how to interact with the `.agents` closure records engine.

## 1. What is a Closure?

A closure is a structured record written with bracket-counting grammar: `()` for identity/arguments, `{}` for field key-values, and `[]` for ordered lists.

```swift
form(id) {
  field1: "value"
  field2: atom
  field3: [item1, item2]
}
```

## 2. The Three Forms of a Record

1. **Draft (`records/drafts/<name>.closure`)**: What the agent writes. IDs are typed as `_`, and fields can appear in any order.
2. **Stored Record (`records/<KIND>/<kind>-<slug>.closure`)**: Canonical 2-space formatted record written only by `.agents/harness/bin/write`.
3. **Human View (`records/<KIND>.md`)**: Read-only Markdown representation generated by `write render`.

## 3. The Lifecycle: How to File a Record

### Step 1: Write the Draft
Always stage your draft in `.agents/records/drafts/<name>.closure`. Match the target template in `.agents/harness/templates/<kind>.closure`.

### Step 2: Check the Draft
Run the checker to verify syntax and field boundaries:
```sh
.agents/harness/bin/write <kind> check-draft .agents/records/drafts/<name>.closure
```
If errors are reported, inspect the line number and fix the exact field. Repeat until it prints `ok: draft passes`.

### Step 3: File the Record
File the draft into its store:
```sh
.agents/harness/bin/write <kind> new .agents/records/drafts/<name>.closure
```
The writer acquires `.write.lock`, mints an 8-character hex ID, sets immutable indexes, canonicalizes layout, and updates the relevant `.md` views.

## 4. Key Placeholder Rules

- `grok("limits")`: Follow line limits (e.g. `<= 8 words`, `no dashes`). Technical words inside backticks count as 1 word.
- `score("min..max")`: Enter a numeric score within the declared range (e.g. `0.95` for `0.0..1.0`).
- `detect()`: Enter `true` or `false`.
- `enum(a, b)`: Enter one of the exact atoms.
- `id()`: Write `_` in drafts; never type an ID.
